# 숫자키 리액션

숫자 키 1~9, 0으로 짧은 연출 10종을 재생합니다. 표정, 팔 제스처, 몸·다리 움직임, 떠다니는 이펙트가 한 번에 움직입니다.
구조는 smiley-vtuber의 리액션 엔진(결정적 타임라인, 레이어, 엔벨로프)을 이 저장소로 옮겨 전신 VRoid 소녀에 맞게 다시 쓴 것입니다. 저장소 사이 import는 없습니다.

공통 규칙입니다.

- 들어올 때 0.15초, 나갈 때 0.35초(끝나기 직전)입니다. 엔벨로프는 smoothstep입니다.
- 같은 키를 다시 누르면 처음부터 다시 재생합니다. 다른 키는 이전 리액션이 0.22초에 걸쳐 나가는 동안 새 리액션이 들어옵니다(교차).
- `Esc`(Electron에서는 맥 `Ctrl+Option+Esc`, Windows `Ctrl+Alt+Esc`)는 0.3초에 걸쳐 접고 FX도 같이 사라집니다.
- 키를 꾹 누르는 반복 입력은 무시합니다. 반복 입력이 리액션을 계속 처음으로 되돌리지 않게 하려는 것입니다.
- 열 개 모두 리액션이 도는 동안 `legsPresent`를 1로 올리고 무릎·골반·발 들기를 목표값으로 섞습니다. 9번 꾸벅 인사는 그 목표값이 전부 0(서 있는 자세)이라, 트래킹 무릎·골반이 움직이고 있어도 숙이는 동안 다리는 제자리입니다.
- 9번은 인사(6번)와 달리 손을 흔들지 않고 점프도 없습니다. 인사와 사과에 같이 쓰도록 웃음·홍조·반짝이를 뺐습니다. 기쁨(1번)과도 겹치지 않습니다(기쁨은 웃는 눈과 깡충깡충).

## 키 배선

| 입력 | 동작 | 구현 |
|---|---|---|
| 숫자 1~9, 0 (창 포커스) | 리액션 재생. 0은 10번 | `src/main.ts` keydown, `e.code`(Digit/Numpad) 우선 |
| Esc (창 포커스) | 리액션 취소와 피커 닫기 | 같은 handler |
| `Ctrl+Option+1`~`9`, `0` (전역, Windows는 `Ctrl+Alt+숫자`) | 리액션 재생 | `electron/main.mjs` globalShortcut. accelerator는 `Control+Alt+숫자` 한 표기로 두 OS를 덮습니다(Alt가 맥의 Option) |
| `Ctrl+Option+Esc` (전역, Windows는 `Ctrl+Alt+Esc`) | 리액션 취소 | 같은 곳. 0이 리액션이라 숫자를 쓰지 않습니다 |
| `⌘1`~`9`, `⌘0`, `⌘-`, `⌘=`, `` ⌘` ``, `⌘[` (Windows는 `Ctrl+` 같은 키) | 캐릭터 전환 | 메뉴 바 accelerator(`CommandOrControl+키`)와 렌더러 keydown(맥 `metaKey`, Windows `ctrlKey`, `src/keys.ts`). 다른 수식키가 같이 눌린 조합(`Ctrl+Alt+숫자`, `⌘⇧…`)은 전환으로 읽지 않습니다. 키는 `shared/avatar-catalog.json` 그대로 |
| `C` | 캐릭터 피커 토글 | 렌더러 keydown |
| 메뉴 바 `리액션`, 우클릭 팝업 `리액션` | 리액션 재생·취소 | `reactionMenuItems()` 공유. 단축키는 표시만 하고 등록하지 않습니다(`registerAccelerator: false`) |

- 리액션 번호와 이름은 `shared/reactions.json`이 단일 출처입니다. Electron 메뉴가 읽고, 테스트가 타임라인과 일치를 검사합니다.
- 키 문자열 규약은 `electron/keys.mjs`에 있습니다(Electron 없이 import 가능).
- 숨겨진 동안(카메라와 렌더 루프 정지)에는 전역 단축키가 와도 보내지 않습니다. 다시 보일 때 옛 리액션이 갑자기 재생되지 않게 하려는 것입니다.
- 전역 단축키를 다른 앱이 쓰고 있으면 그 키만 등록에 실패하고 콘솔에 경고만 남깁니다.

## 파이프라인

```
tracking → aliveness → reactions.compose → model.apply
```

`reactions.compose(frame, dt, t)`는 aliveness가 방금 만든 프레임을 그 자리에서 고쳐 쓰고 그대로 돌려줍니다. 리액션이 없으면 프레임을 건드리지 않고 `frame.motion`·`frame.expr`도 만들지 않습니다.
레이어 하나는 리액션 하나(타임라인 + 엔벨로프 가중치 w)입니다. 최대 3개가 겹치고, 시작이 오래된 것부터 차례로 덮어씁니다.

| 채널 | 합성 방법 |
|---|---|
| 눈 깜빡임, 윙크, 시선, 입 벌림, 미소 | `lerp(트래킹, 목표, w)`. 타임라인이 NaN으로 두면 트래킹 값이 그대로 흐릅니다 |
| 표정 가중치(happy, sad, angry, surprised, relaxed) | 레이어 사이는 max, 모델에서 다시 트래킹 값과 max |
| 홍조 | `lerp` |
| 모델 머리 FX 플래그(하트, 땀, 분노) | 들어올 때 w가 0.35를 넘고 나갈 때 0.12 아래로 내려가기 전까지, 가장 최근 레이어가 정합니다 |
| 머리 pitch/yaw/roll, 몸 lean/twist/shrug | 더합니다. 트래킹이 계속 살아 있습니다 |
| 다리(legsPresent, 무릎, 골반) | legsPresent는 max, 무릎·hipShift는 목표값으로 섞습니다(트래킹 무릎이 0이 아닐 수 있어 더하지 않습니다) |
| 몸 움직임(bounce, shiftX, 발 들기·차기·벌림) | `Σ 목표 × w` |
| 자전(spin) | 들어오는 중에는 그대로, 나가기 시작하면 그 시점 값에서 가장 가까운 정수 바퀴로 풀립니다 |
| 팔 방향 4개, 손가락, 벌림 | 레이어 목표끼리 먼저 쌓고(가중치 합 `1-(1-a)(1-b)`), 프레임 팔과는 한 번만 섞습니다 |

팔 방향은 성분 lerp가 아니라 구면 보간입니다. 두 방향이 둔각 이상(내린 팔과 만세 등)이면 회전 평면이 두 벡터 외적의 미세한 차이로 정해져서, 레이어 교차 중에 손 방향이 한 프레임에 50° 넘게 튀었습니다.
그래서 각이 벌어질수록 옆 방향을 제어점으로 하는 2차 구면 베지에로 보간합니다(`src/reactions/util.ts`). 임계값 스위칭이 없어서 경로가 연속으로 변하고, 팔은 언제나 몸 옆으로 벌어지며 올라갑니다.

## 결정성

같은 (트리거 순서, 시각)이면 같은 그림입니다.

- 시간은 호출자가 넘기는 `t`뿐입니다. `Date.now()`나 `performance.now()`를 쓰지 않습니다.
- 난수는 트리거마다 시드가 정해진 `mulberry32`뿐입니다(`Math.random()` 없음). 시드는 `리액션 번호 × 7919 + 트리거 횟수 × 104729 + 12345`입니다.
- FX 입자의 위치·크기·불투명도는 나이(age)의 닫힌 식입니다. 프레임 사이에 적분하지 않아서 프레임레이트와 무관합니다.
- 하네스는 1/60초 스텝으로 트리거부터 돌립니다.

## 계약 변경 (선택 필드만)

`src/contract.ts`에 선택 필드만 더했습니다. 트래킹과 aliveness는 그대로입니다. 필드가 없으면 모델은 이전과 똑같이 움직입니다.

- `FxState.blush?`: 볼 홍조 0..1
- `RigFrame.motion?: BodyMotion`: `bounce`(도약), `spin`(루트 y 회전, 누적 rad), `shiftX`(좌우 이동)는 키 대비 비율입니다. `liftL/R`(발 들기), `kickL/R`(다리 차기), `outL/R`(다리 벌림 rad), `snap`(몸 채널 스무딩 우회 0..1), `bow`(허리 숙임 rad, +앞)도 있습니다. 트래킹은 `motion`을 만들지 않으므로 `bow`는 리액션에서만 생깁니다.
- `RigFrame.expr?: ExprOverride`: happy, sad, angry, surprised, relaxed 가중치
- `MingoModel.anchors?`, `anchorsOn?`: FX가 붙는 월드 좌표(몸, 머리, 눈, 손, 발)와 갱신 스위치

## 모델 쪽 변경 (`src/model/index.ts`)

- 도약·자전·좌우 이동은 `avatarRoot`(root의 자식, `vrm.scene`의 부모)에 겁니다. `root`에는 고정 조명이 붙어 있어서 yaw를 걸면 빛이 같이 돌고, `vrm.scene`은 `rotateVRM0`가 이미 y=π를 쓰고 있습니다. 몸, 후드, 머리카락(VRM 스프링 본)만 돌고 조명은 그대로입니다.
- 표정은 트래킹에서 나온 값과 `max`로 합칩니다. Joy(웃는 눈)는 눈을 이미 감은 모양이라 깜빡임을 같이 감쇠합니다.
- VRoid(VRM0)는 놀람 표정을 `unknown` 프리셋의 커스텀 이름 `Surprised`로 내보내서 three-vrm이 소문자 `surprised`로 등록하지 않습니다. 둘 다 찾아 둡니다. 트래킹 눈썹 → 놀람 매핑은 기존과 같이 소문자를 가진 모델에서만 동작합니다.
- `motion.snap`이 켜진 동안 몸 채널 스무딩(τ 0.1초)과 다리 게이트(τ 0.25초)를 거의 즉시(τ 0.02, 0.04초)로 바꿉니다. 박자(2Hz)가 평활에 뭉개지지 않게 하려는 것입니다.
- 같은 `snap`으로 골반 좌우 이동·롤을 2.8배로 키우고(`BODY.snapHipMul`) 팔 present 크로스페이드 시정수를 0.12초에서 0.04초로 줄입니다. 트래킹의 `hipShift=1`은 다리 길이의 6%(약 5cm)라 춤의 체중 이동이 오버레이 크기에서 보이지 않았습니다. 트래킹은 `snap`을 쓰지 않아서 영향이 없습니다.
- 다리는 두 갈래입니다. 기존 `knee`(허벅지 전방, 정강이 수직, 발 접지 보정)는 그대로이고, 리액션 전용으로 발 들기(허벅지 0.5rad, 정강이 절대 -1.5rad), 차기(무릎을 편 채 1.0rad), 옆으로 벌림(±0.7rad)을 더했습니다. 접지 보정은 `knee`만 기준이라 도약과 발 들기는 타임라인의 `bounce`가 책임집니다.
- 허리 숙임(`motion.bow`, 꾸벅 인사): 골반(hips)을 앞으로 접고(로컬 x 회전 `-S·bow`, 몸통 lean과 같은 규약) 허벅지에 같은 각을 되돌려 다리를 월드에서 곧게 세웁니다. 접는 축은 hips 원점이 아니라 두 고관절의 중점이라서, 접은 만큼 hips 위치를 `c - R·c`로 옮겨 고관절이 제자리에 남게 합니다. 그래서 허벅지·정강이·발은 월드에서 움직이지 않고 상체만 고관절을 축으로 접힙니다. 수식은 `src/model/bow.ts`의 순수 함수이고(`S` = VRM0 +1, VRM1 -1 모두), 한도는 `BOW_MAX`(1.0rad)입니다. `bow`가 0이면 변환이 이전과 같습니다. lean과 달리 척추를 굽히지 않아 상체가 곧은 채로 숙여지고, 팔은 몸통을 따라가므로 숙이는 동안 타임라인이 팔을 곧게 펴 손이 허벅지 앞에 오게 합니다. 꼬리가 있는 종(여우·고양이·강아지·호랑이·원숭이)은 `update`의 선택 인자 `bow`로 팔로스루를 합니다: 꼬리 밑동 피벗이 접힘의 0.8배(`TAIL_LIFT`)를 되돌려 꼬리가 등에서 떠 서 있을 때와 비슷한 방향(수직 기준 약 30° 뒤)에 머물고, 가닥 분절마다 지연 스프링이 따로 따라가(끝으로 갈수록 늦다) 내려가는 동안은 끝이 뒤로 약 14°, 일어서는 동안은 앞으로 약 12° 처졌다 돌아오며, 머무는 동안 끝이 자기 무게로 완만하게 처집니다(`BOW_SAG`). `bow`가 0이면 이전 모션과 같고 2.5초 넘게 서 있으면 지연 스프링 계산도 건너뜁니다.
- 볼 홍조(`src/model/cheeks.ts`, `fx.ts`): 얼굴형 워프가 종마다 눈과 얼굴을 옮겨서 눈 본 위치를 믿을 수 없습니다. 홍채(EyeIris) 정점 중심을 눈 위치로, 얼굴 피부(Face_00_SKIN) 정점에서 볼 자리의 가장 앞쪽 표면 z를 읽어 로드 때 한 번 배치합니다. 부드러운 방사형 캔버스 텍스처를 입힌 평면 두 장입니다.
- FX 앵커: `anchorsOn`이 켜진 동안에만 `apply`가 월드 행렬을 갱신해서 앵커를 채웁니다. 리액션이 도는 동안(떠 있는 FX 포함)만 엔진이 켭니다.

## FX

`src/reactions/fx.ts`입니다. 하트, 반짝이, 꽃 3색, 색종이, 느낌표, 눈물·땀방울, 분노 마크, 먼지, 음표 두 종류를 캔버스로 그린 텍스처 12장과 `THREE.Sprite` 128개 풀입니다.

- 좌표 단위는 아바타 키 1입니다. `fxRoot`가 키만큼 스케일되고 발밑이 y=0, 머리 위가 y≈1입니다.
- 입자는 앵커(몸, 머리, 눈, 손, 발)에 붙어서 태어납니다. `follow` 0..1은 태어난 뒤 앵커가 움직인 만큼 따라가는 비율입니다.
- 스프라이트마다 `SpriteMaterial`이 따로 있어서 불투명도와 색을 개별로 줍니다. 생성할 때 맵만 바꿔 끼웁니다.
- `depthTest`를 끄고 `renderOrder` 20으로 항상 캐릭터 앞에 그립니다. 평면 스티커입니다.
- 위치는 `p0 + v·(1-e^(-k·age))/k - ½·g·age²`(감쇠 + 중력)에 흔들림과 따라가기를 더한 식입니다.
- 풀이 차면 새 입자는 만들지 않고 건너뜁니다. 가장 많이 뜨는 리액션도 동시에 21개 안팎입니다.
- 시작할 때 셰이더를 한 번 미리 컴파일합니다(`warm.ts`). 처음 누른 키의 등장 중에 컴파일이 돌아 프레임이 끊기는 것을 막습니다.

## 카메라

만세와 점프가 창(560×780) 밖으로 잘리지 않게, 리액션마다 `pull`(0.03~0.14)만큼 엔벨로프를 따라 카메라가 뒤로 빠집니다(`src/framing.ts`, main.ts와 하네스가 같은 식을 씁니다). 점프 공간을 위해 시선도 살짝 올립니다.

`reaction=0`은 10번(귀여운 춤)입니다. 모델 단독 검증용 쿼리(`bounce`, `spin`, `liftL`, `xHappy`, `blush` 등)도 `harness.ts` 머리말에 있습니다.

`npm run test:reactions`(`node scripts/test-reactions.mjs`)는 브라우저 없이 엔진을 검증합니다. 캔버스는 가짜로 대신합니다.

- 결정성: 두 엔진의 같은 시각 프레임과 FX 스프라이트 상태가 일치하고, `src/reactions/**`에 `Math.random`·`Date.now`·`performance.now`가 없습니다.
- 엔벨로프: 10종 전부 트리거 직후는 베이스와 같고, 끝나면 모든 채널이 정확히 베이스로 돌아오고 `active()`가 null이며 `motion`·`expr`가 없고 FX가 사라집니다.
- 교차(9 → 3, 10 → 6, 1 → 4): 스칼라 채널은 프레임당 0.4 미만, 팔 방향은 프레임당 0.6rad 미만으로 변합니다. 같은 키 재시작은 FX 이벤트를 다시 발생시킵니다.
- 취소: 0.5초 뒤 베이스로 복귀합니다. 트월 도중 취소해도 자전은 가장 가까운 정수 바퀴 쪽으로 반 바퀴 안에서만 풀립니다.
- 트래킹 통과: 인사 중 머리 yaw와 시선은 트래킹 값 그대로이고, 더하는 채널(부끄러움의 머리 yaw)은 트래킹 값 위에 얹힙니다. 춤 중 무릎은 트래킹 값이 아니라 리액션 목표로 섞입니다.
- 열 개 전부: 값이 유한하고, 점프가 바닥 아래로 내려가지 않고, 표정·홍조·무릎이 범위 안이고, 끝나면 자전이 정수 바퀴이고, `compose`가 입력 프레임을 그대로 돌려주고 `motion`·`expr` 객체를 재사용하고, 다리를 씁니다(`legsPresent` ≥ 0.9).
- 귀여운 춤(0번): 무릎이 굽고, 발이 들리고, 골반이 옮겨지고, 한 바퀴를 돕니다.
- 꾸벅 인사(9번): 숙인 구간(1.05~1.55초)에서 `bow`가 0.6rad로 일정하고 고개는 -0.06rad, 척추 lean·twist는 0이며, 일어선 뒤와 끝나면 0입니다. `bow`는 프레임당 0.06rad 미만으로 부드럽게 변합니다. 발 들기·차기·점프·좌우 이동·자전·골반 이동이 전부 0이고 무릎은 0.05 이하이며 이펙트가 없습니다. 표정은 홍조 0, 입 다묾, 미소 0.2 이하, 숙인 동안 blink 0.6 이상입니다. 트래킹 골반 이동·무릎이 있어도 숙이는 동안 0으로 섞입니다. 다른 아홉 개는 `bow`를 쓰지 않습니다.
- 허리 숙임 수식(`src/model/bow.ts`): 모델이 hips·허벅지에 넣는 값으로 만든 가짜 골격에서(VRM0 S=+1은 씬을 π 회전, VRM1 S=-1) bow 0.2~1.0 모두 고관절·무릎·발의 월드 위치가 1e-9 안에서 그대로이고, 머리가 +z(카메라 쪽)로 가며 상체 축이 수직에서 bow만큼 기웁니다. 부호나 역회전을 틀리게 바꾸면 이 검사가 깨집니다.
- 꼬리 팔로스루(`src/model/strands.ts`, `bodyParts.ts`): bow = 0이면 x 굽힘이 0 그대로(인자 생략과 같음), 숙인 채 머물면 끝이 뒤로 처져 자리 잡고, 내려갈 때 정상값보다 더 뒤로·일어설 때 앞으로(0 아래) 처졌다가 5초 안에 0으로 돌아오고, 끝의 팔로스루가 밑동보다 큽니다. 꼬리 밑동 되돌림은 VRM0·VRM1 모두 bow 0.6에서 꼬리 방향이 서 있을 때와 ±0.3rad 이내입니다(강체로 따라가면 -0.6rad, 부호를 틀리면 -1rad 가까이). 자동 테스트는 아니고 CDP 로 한 번 잰 값입니다: 숙임 한 사이클 동안 꼬리 분절 점이 척추 축에 가까워지는 최소 거리가 5종 모두 밑동 거리(0.208)이고 그 아래로 내려가지 않아, 꼬리가 등을 파고들지 않습니다.
- 앵커: 트리거하면 `anchorsOn`이 켜지고 FX가 모두 사라지면 꺼집니다. 입자는 모델 앵커(월드)를 키로 나눈 위치에 태어납니다.
- 할당: 워밍업 뒤 프레임당 힙 증가량이 2KB 미만입니다. 실수 박싱 때문에 800B 안팎은 나옵니다.
- `shared/reactions.json`과 타임라인 일치, Electron 키 규약(전역 단축키 10개와 취소 키, 캐릭터 메뉴 accelerator 14개의 형식과 중복 없음).

## 리액션 추가하기

1. `src/reactions/timelines.ts`에 `Spec`을 만듭니다. `eval(tl, tg)`는 시간(초)만 받는 순수 함수이고 `tg`(Target)를 채웁니다. `KEEP`(NaN)인 채널은 건드리지 않습니다. 다리를 쓰면 `tg.legs = 1`로 올립니다.
2. 팔은 `armSet(tg, 0 또는 1, 강도, G.제스처)` 후 `nudge`로 흔들고, 구간별 제스처는 `armBlendTo`로 이어 붙입니다. 제스처는 `poses.ts`의 `G`에 캐릭터 왼팔 기준으로 `{u, bend, elbow, palm}` 또는 전완 방향 직접 지정으로 적습니다.
3. FX는 `events`에 `{ t, run }`을 넣습니다. `fxlib.ts`의 발사기를 쓰거나 `fx.emit(종류, 앵커, 오프셋)`가 돌려주는 입자의 필드를 채웁니다. 난수는 `run`이 받는 `rng`만 씁니다.
4. `SPECS` 배열, `shared/reactions.json`, 키를 맞춥니다. 테스트가 일치를 검사합니다.
5. 하네스로 `reaction=N&strip=8`과 클로즈업을 보고 `npm run test:reactions`를 돌립니다.

## 알려진 한계

- 손은 얼굴·몸과 충돌하지 않습니다. 볼과 눈가를 감싸는 제스처는 손 위치를 눈으로 맞춘 값이라 종마다 얼굴 크기가 달라 약간 어긋날 수 있습니다.
- 높은 킥에서는 짧은 치마 안쪽 레이어가 보이거나 다리가 치마를 뚫을 수 있습니다. 치마는 VRM 스프링 본이라 충돌 보정이 없습니다. 귀여운 춤의 킥을 토 탭(허벅지 0.35rad)으로 줄인 이유입니다.
- 골반 이동은 골반만 옮기고 발을 고정(IK)하지 않습니다. 체중이 실린 발이 골반과 함께 약간 미끄러집니다.
- 트월 뒷모습에서는 후드와 꼬리만 보입니다. 꼬리·후드 가닥은 머리 pitch/yaw 로만 흔들리고 루트 회전의 관성은 받지 않습니다. 옆모습에서 꼬리가 뒤로 뻗어 보이는 것은 정지 자세의 실루엣입니다.
- 트월 중 취소하면 자전이 반 바퀴 이내로 되감깁니다(0.3초).
- 볼 홍조는 평면 두 장입니다. 고개를 많이 돌리면 가장자리가 윤곽 쪽으로 번질 수 있습니다.
- 9번 꾸벅 인사는 정면에서도 숙인 동안 후드 개구부 아래로 감은 눈과 코가 보입니다(허리 34° + 고개 0.06rad). 43° + 0.2rad 였을 때는 정점에 후드 윗면만 보여 머리 없는 덩어리처럼 읽혔습니다. 더 깊게 숙이면(대략 0.75rad 이상) 다시 얼굴이 가려집니다. 오버레이 실제 크기(키 300px 안팎)에서도 얼굴 윤곽은 읽히지만 표정 세부(입꼬리)는 뭉개집니다.
- 허리를 숙이면 짧은 치마 뒷자락이 hips 회전을 따라 위로 들려 보일 수 있고, hips에 붙은 꼬리는 골반과 같이 기울지만 밑동에서 접힘의 0.8배를 되돌리고 분절마다 늦게 따라가므로 수직 막대로 서 있지 않습니다(`TAIL_LIFT`, `BOW_LAG_GAIN`, `BOW_SAG`). 치마는 VRM 스프링 본이라 충돌 보정이 없습니다.
- 모든 리액션이 다리를 강제하므로, 전신 트래킹 중에 리액션을 재생하면 그동안 사용자의 무릎은 반영되지 않습니다.
- `` ⌘` ``(플라밍고)는 macOS가 창 순환 단축키로 먼저 가져갈 수 있습니다. 이 경우 칩이나 피커로 전환합니다.
- 브라우저로 열었을 때(`npm run dev`를 브라우저에서) `⌘1`~`9`, `⌘0`, `⌘-`, `⌘=`(Windows는 `Ctrl+1`~)는 브라우저가 먼저 가져갑니다(탭 전환, 확대·축소). 이 경로의 캐릭터 전환은 칩이나 피커를 씁니다. Electron에서는 메뉴 accelerator가 처리합니다.
- 오버레이 창은 클릭스루라 맨 숫자 키는 창을 한 번 클릭해 포커스를 준 뒤에만 먹습니다. 평소에는 `Ctrl+Option+숫자`(Windows는 `Ctrl+Alt+숫자`)가 주 경로입니다.
- Windows에서 AltGr(= Ctrl+Alt)로 글자를 입력하는 자판은 `Ctrl+Alt+숫자`가 글자 입력과 겹칠 수 있습니다. 이 경우 창 포커스의 맨 숫자 키나 메뉴의 `리액션`을 씁니다.
- `anchorsOn` 동안 `apply`가 월드 행렬을 한 번 더 갱신합니다(렌더러가 한 번 더 합니다). 리액션이 도는 동안만 드는 비용입니다.
- 할당 테스트의 한도(2KB/프레임)는 Node 26 기준 측정치(≈780B) 위에 둔 값입니다. CI의 Node 22에서는 V8 박싱 동작이 달라 흔들릴 수 있습니다.
- 메뉴 accelerator와 전역 단축키는 Electron을 띄워 등록 성공까지 확인했지만, 실제 오버레이 창에서 사람이 눌러 본 것은 아닙니다. Windows(`CommandOrControl`·`Control+Alt` 표기)는 macOS에서 문자열과 순수 로직만 검증했고 Windows 실기에서는 확인하지 못했습니다. 실제 웹캠 트래킹 위에서 리액션이 이어지는 느낌도 하네스와 가짜 입력으로만 확인했습니다.
